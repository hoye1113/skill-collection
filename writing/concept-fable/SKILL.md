# Concept Fable

## 哲学（为什么用寓言）

直接讲是定义。寓言是**让读者自己撞上概念**——概念不出现，藏在场景、动作、对话的肌理里；读者读完合上书，恍然明白「哦，原来讲的是这个」。

直接讲的好处是快、可证伪。寓言的好处是**留下钩子**——读者不会忘记自己撞上的东西，因为那是他自己得出的结论，不是被灌输的。

> 寓言不是装饰，是认知位移的载体。「读完仍不知道是什么」是失败（钩子没挂上）；「读完立刻知道是什么」也是失败（没位移）。**合上书半分钟后才恍然**，是成功。

## 核心约束（不可破）

### 篇幅
**≤ 1000 字**。真正的寓言是精炼的——一个核心场景、一两次转折，把意思撑起来。不要铺陈，不要渲染，不要抒情。

### 角色
**≤ 3 个，最好 2 个**。角色多 = 寓意被稀释。**角色之间的关系或互动本身承载寓意**，不是角色的台词。

### 揭示节奏
**全程不出现概念名，不使用该领域术语。** 只在接近结尾时，让读者隐约意识到讲的是什么。如果概念名在文中出现，寓言就死了——直接讲和绕弯讲是两回事。

### 叙事纪律
**让情节和细节本身承载意义。** 不要让角色跳出来当解说员（「你看，这就是 X」）。角色的反应、动作、对话，应该让读者自己推断。

### 不要写成
- ❌ 散文诗 / 抒情片段
- ❌ 哲理短句堆砌（每段一句话讲一个道理）
- ❌ 现代背景的现实主义小故事（除非能拟人化）
- ❌ 「我要告诉你一个道理」式的开场白

## 流程

```
输入：{concept}
   ↓
1. 拆解概念：核心机制是什么？矛盾点是什么？典型场景是什么？
   ↓
2. 选切入角度（参考 references/angles.md，30+ 候选）
   ↓
3. 设计场景骨架：
   - 谁（角色身份，避免黑名单）
   - 在哪里（场景，避免过度文艺化地名）
   - 一次冲突 / 一次转折
   - 结尾如何留痕（让读者自己撞上概念）
   ↓
4. 黑名单自检（参考 references/blacklist.md，5 类）
   ↓
5. 写寓言正文（不加标题不加引导语）
   ↓
6. 写概念解析：定义 + 元素映射
   ↓
7. 提 2 个检验问题（具体可答，不空泛）
```

## 切入角度（优先级排序）

### 第一优先：非人类视角
一件工具、一只动物、一种植物、一个机构在自述。优势：天然去人类中心化，读者不会预设立场。
- 工具：电梯、计算器、门锁、缝纫机、压面机
- 动物：候鸟、蜜蜂、蚂蚁、章鱼、鸽子
- 植物：榕树、苔藓、蒲公英、菌丝
- 机构：公司、医院、学校、监狱、图书馆

### 第二优先：具体现代职业
理赔员、电梯保养工、菜市场摊主、夜班护士、外卖站长、二手房中介、分拣员、加油站员工、擦鞋匠、配镜师。优势：**高度具体**，让故事的「真实感」承载概念。
- 完整职业列表见 references/angles.md

### 第三优先：微观尺度
一次交易、一次门诊、一通电话、一次拆卸、一次擦肩、一次堵车。优势：聚焦一个动作或瞬间，把概念掰开了看。

> 核心原则：**让故事的具体性把概念裹住**。抽象寓言（用「时间」「命运」当主角）容易滑向哲理短句。

## 输出格式

### 第一部分：寓言正文
直接输出故事。**不加标题、不加引导语、不加注释。** 第一行就是故事本身。

### 第二部分：概念解析
另起一段（用 `---` 或 `###` 分隔），完成以下内容：

1. **讲清楚这个概念叫什么、属于哪个流派或学科、核心定义是什么**（2-3 句）
2. **逐一对应：故事里的哪些元素映射到概念的哪个部分**
   - 例：「`角色 A` 持续投入却不退出 → 已付出且不可收回的成本」

### 第三部分：检验问题
向我提两个问题：

1. **理解检验**：检验我是否真正理解了概念的核心（不只是记住了故事情节）。问题要具体可答。
   - ✅「故事里角色 B 为什么不离开？」
   - ❌「你怎么看待这个概念？」

2. **迁移检验**：检验我是否能把这个概念迁移到相关领域。问题要具体可答。
   - ✅「如果用这个概念分析 [具体场景]，会得出什么结论？」
   - ❌「这个概念还能用在哪里？」

## 检验 / 自检

写完寓言后，逐项检查：

- [ ] 字数 ≤ 1000？
- [ ] 角色 ≤ 3 个？
- [ ] 全文 grep 概念名（中文 + 英文）= 0 命中？
- [ ] 全文 grep 该领域的术语（如「算法」「均衡」「拓扑」「博弈」等）= 0 命中？
- [ ] 意象黑名单 5 类全过？
- [ ] 没有角色跳出来讲解（「你看，这就是……」）？
- [ ] 结尾有没有留痕（让读者读完半分钟后恍然）？
- [ ] 概念解析的元素映射是否一一对应？
- [ ] 检验问题是否具体可答（不是开放题）？

## 成功标准

- **寓言部分**：凉脑子瞥一眼，隐约能意识到讲的是什么，但不刺破
- **概念解析**：让一个没听过这个概念的人读完能讲清楚
- **检验问题**：让读者必须思考才能答（不是「你怎么看待 X」式空泛）

## 使用方式

### 标准流程
```
用户：「用寓言讲讲沉没成本」
→ 拆解概念（已付出且不可回收的成本影响后续决策）
→ 选角度（用候鸟迁徙的体能消耗 / 二手书店的进货）
→ 写寓言
→ 概念解析
→ 2 个检验问题
```

### 自带概念
```
用户：「/concept-fable 内卷」
→ 直接进入拆解和写作
```

### 调试模式
```
用户：「/concept-fable 沉没成本，但用保险理赔员的视角」
→ 用户指定角度时优先采用，但保留黑名单自检
```

## 反例（每条都是真实踩过的坑）

| # | 反例 | 为什么错 | 替代 |
|---|---|---|---|
| 1 | 寓言中出现概念名 | 钩子失效，等于直接讲 | 用隐喻对象替代（如「沉没成本」→「那笔退不掉的钱」） |
| 2 | 角色开口讲解 | 破坏叙事纪律 | 让动作 / 对话 / 结果承载含义 |
| 3 | 意象命中黑名单 | 陈词滥调，读者出戏 | 替换为具体的职业 / 工具 / 微观动作 |
| 4 | 检验问题空泛 | 读者答不上来或随便答 | 问具体的、可论证的子问题 |
| 5 | 字数超 1000 | 寓言 = 精炼，不是铺陈 | 砍场景、砍角色、砍旁白 |
| 6 | 角色 4+ 个 | 寓意稀释 | 砍到 2-3 个 |
| 7 | 概念解析元素映射不一一对应 | 读者无法把故事和概念连接 | 每个映射写一行，明确指出 |

## 设计哲学

> 「寓言不是简化，是浓缩。」
> 一千字以内的虚构场景，要让读者自己得出结论。
> 解释权在读者手里，作者只负责把场景摆好。
